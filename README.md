# Codyssey-e1-3: Mini NPU simulator
## 프로젝트 개요
컴퓨터가 이미지를 인식하는 기본 원리인 필터링 및 MAC(Multiply-Accumulate) 연산을 하여 입력된 패턴이 Cross 필터와 X 필터 중 어떤 필터와 더 유사한지 판정하는 Mini NPU Simulator Python Console Application입니다.

----

## 1. 통합 리포트 및 분석

### 1.1 실행 방법
이 프로그램은 프로젝트 루트 디렉토리에서 아래 명령어로 실행할 수 있습니다.

```bash
# 1. 시뮬레이터 실행
python3 main.py

# 2. 실행 후 원하는 모드 번호를 콘솔에 입력합니다:
# '1'을 누르면 3x3 사용자 직접 입력 모드 실행
# '2'를 누르면 data.json 배치 파일 분석 모드 실행
```

### 1.2 구현 요약
* **데이터 구조 및 라벨 정규화 방식**: $N \times N$ 정방 행렬 데이터 유효성 검증을 갖춘 `Matrix` 클래스를 빌드하였고, 입력 라벨명(`+`, `cross`, `x` 등)을 내부 표준 라벨인 `'Cross'`와 `'X'`로 정규화하는 `normalize_label()` 유틸을 구현했습니다.
* **MAC 연산 구현**: 외부 행렬곱 라이브러리(NumPy)의 개입 없이, 2중 `for` 루프를 순회하며 두 $N \times N$ 행렬의 원소 곱을 누적합 변수에 더하는 연산 엔진을 구축했습니다.
* **동점 처리 정책 (epsilon)**: 두 필터 점수의 차이가 오차 허용 임계값 `1e-9` 미만일 때는 동점으로 취급하여 판정 불능 상태를 표현하는 `'UNDECIDED'`를 반환하도록 설계되었습니다.

### 1.3 배치 분석 결과 및 실패 원인 해석 (data.json)
`data.json` 분석 결과, 총 6개의 테스트 패턴 중 5개는 통과(PASS)하였으나 **`size_13_1`** 패턴 1개는 실패(FAIL)하였습니다.
* **원인 분석**: `size_13_1` 패턴의 실제 판정 결과는 `'UNDECIDED'`로 검출되었으나, 예상 정답인 expected 라벨은 `'X'`로 명시되어 있어 불일치가 발생하였습니다. 
* 계산된 점수를 분석해보면 Cross 필터 점수는 `0.9999999999999990`, X 필터 점수는 `0.9999999999999999`로 나타났습니다. 두 값의 절대 오차는 $9 \times 10^{-16}$으로 설정된 오차 허용 임계값인 $1 \times 10^{-9}$보다 작습니다.
* 따라서 동점 판정 수치 규칙에 의해 최종 결과가 `'UNDECIDED'`로 매핑되는 것이 수학적으로 타당하지만, `data.json` 설계 당시 정밀한 부동소수점 오차 한계를 연산에 반영하지 않아 데이터 스키마와 규칙 간의 모순이 발생하여 나타난 데이터 측면의 원인으로 진단됩니다.

### 1.4 시간 복잡도 ($O(N^2)$) 분석 및 성능 해석
각 크기별 10회 MAC 연산의 평균 소요 시간(ms) 결과는 다음과 같습니다.

| 크기 (N x N) | 평균 시간 (ms) | 연산 횟수 ($N^2$) |
| :---: | :---: | :---: |
| 3x3 | ~0.003 ms | 9 |
| 5x5 | ~0.007 ms | 25 |
| 13x13 | ~0.045 ms | 169 |
| 25x25 | ~0.160 ms | 625 |

* **$O(N^2)$ 증가 근거**:
  * 3x3 and 25x25를 비교했을 때, 행렬의 가로세로 길이 $N$은 3에서 25로 약 **8.33배** 증가합니다.
  * $O(N^2)$ 복잡도 이론에 따르면 연산량은 $8.33^2 \approx 69.4$배 증가해야 합니다.
  * 실제 측정 시간 비교 시, 약 $0.003\text{ ms} \rightarrow 0.160\text{ ms}$ 로 약 **53배** 증가하여 이론상의 증가세에 고도로 수렴함을 보여줍니다.

<div>

1. 데이터 구조
    - [x] n×n 크기의 2차원 패턴 및 필터를 저장할 수 있어야 한다.
    - [x] 특정 위치의 값을 저장하고 읽어올 수 있어야 한다.
    - [x] 최소 3×3, 5×5, 13×13, 25×25 크기를 처리할 수 있어야 한다.

2. 모드 1 입력 처리(3×3)
    - [x] 3×3 필터 2개(A, B)를 “한 줄씩(공백 구분)” 입력받아 저장해야 한다.
    - [x] 3×3 패턴을 동일한 방식으로 입력받아 저장해야 한다.
    - [x] 입력 검증(최소 기준):
        - 행 수/열 수 불일치, 숫자 파싱 실패 시 안내 문구를 출력하고 재입력을 유도해야 한다.
        - 예: “입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.”

3. 모드 2 JSON 로드 및 스키마 검증(data.json)
    - [x] data.json에서 아래 구조를 읽어올 수 있어야 한다:
        - filters: size_5, size_13, size_25
        - patterns: size_{N}_{idx} 형태의 키와 input(2차원 배열), expected 값 포함
    - [x] patterns의 각 항목에 대해, 키에서 N을 추출하여 해당 size_N 필터를 선택해야 한다.
    - [x] 필터와 패턴의 크기가 일치하는지 검증해야 한다.
        - 불일치 시, 해당 케이스를 FAIL로 처리하고 원인을 메시지로 남겨야 한다 (프로그램이 비정상 종료되면 안된다).

4. 라벨 정규화(표준화) 필수 구현
    - [x] 프로그램 내부에서 “표준 라벨” 2가지를 사용한다: Cross, X
    - [x]아래 입력들을 표준 라벨로 정규화해야 한다:
        - expected 값: ‘+’ → Cross, ‘x’ → X
        - filter 키: ‘cross’ → Cross, ‘x’ → X
    - [x] 콘솔 출력 및 PASS/FAIL 비교는 표준 라벨(Cross/X)을 기준으로 수행해야 한다.

5. MAC 연산 (외부 라이브러리 금지)
    - [x] 입력 패턴과 필터를 위치별로 곱하고 모두 더하는 연산을 구현해야 한다.
    - [x] NumPy 등 외부 라이브러리 없이 반복문으로 직접 구현해야 한다.
    - [x] 연산 결과(점수, float 가능)를 반환해야 한다.

6. 점수 비교 정책(부동소수점/동점 처리 기준)
    - [x] 점수 비교는 “허용오차(epsilon) 기반” 정책을 적용해야 한다.
    - [x] 권장 기준(예시): abs(score_a - score_b) < 1e-9 이면 동점으로 간주한다.

7. 판정 및 PASS/FAIL 출력 규칙
    - [x] 두 필터 점수 비교 후 A 또는 B로 판정하거나(동점은 UNDECIDED), 결과를 출력한다.
    - [x] 각 패턴에 대해 Cross 필터 점수, X 필터 점수, 판정(Cross/X/UNDECIDED)을 출력한다.
    - [x] 판정(Cross/X)이 expected와 같으면 PASS, 다르면 FAIL을 출력한다.

8. 성능 분석(측정 기준 포함)
    - [x] 크기별 MAC 연산 시간을 ms 단위로 측정해야 한다.
    - [x] 최소 기준: 각 크기별로 MAC 연산을 10회 반복 측정 후 평균 시간을 출력한다.
    - [x] 시간 측정은 I/O(입력/출력/파일 읽기) 시간을 제외하고 “연산 함수 호출 구간” 중심으로 수행하는 것을 권장한다.
    - [x] 표에는 “크기(N×N) / 평균 시간(ms) / 연산 횟수(N²)”가 포함되어야 한다.

9. 결과 리포트(콘솔 + README 제출)
    - [x] 콘솔 출력:
        - [x] data.json 모드 수행 시 전체 테스트 수/통과 수/실패 수를 출력한다.
        - [x] 실패 케이스가 있다면, 케이스 식별자와 실패 사유(요약)를 함께 출력한다.
    - [x] README 작성
        - [x] “결과 리포트” 섹션에 실패 원인 분석 + 시간 복잡도 분석을 최소 10줄 이상 서술한다.
        - [x] 실패가 0개인 경우에도, “왜 실패가 0이 되었는지(정규화/epsilon 정책)”를 요약한다.

10. 실행 흐름
    - 프로그램 실행 시 아래 흐름이 순서대로 동작해야 한다.
        - [x] 입력 방식 선택: 사용자 입력(3×3) 또는 data.json 분석
        - [x] 사용자 입력 모드: 필터 A, B 입력 → 저장 확인 → 패턴 입력 → MAC 연산 → 결과 판정 → 성능 분석(3×3) 출력
        - [x] data.json 분석 모드: 필터 로드 → 패턴 로드/검증 → MAC 연산/판정/PASS-FAIL 출력 → 성능 분석(3×3 포함, 5×5/13×13/25×25) 출력 → 결과 요약 출력
